# Use Cases and User Journeys

## First-time user: create and secure a wallet
1. User creates a wallet.
2. User records the recovery phrase privately and offline.
3. User confirms the backup process.
4. User enters the wallet and chooses a supported network or asset view.

**Agent guidance:** Emphasize backup responsibility. Never request the recovery phrase in chat.

## User receives crypto
1. User selects the right network and asset.
2. User opens Receive or shows a QR code/address.
3. Sender transfers funds using the matching network.
4. User checks activity after the network confirms the transaction.

**Key warning:** A token sent on an incompatible network may not arrive as expected.

## User sends crypto
1. User chooses asset and network.
2. User enters or scans a recipient address.
3. User enters amount and reviews available balance and fee.
4. User reviews destination, network, amount, and total cost.
5. User confirms only after checking the details.

**Key warning:** Blockchain transactions are generally irreversible once confirmed.

## User connects to a dApp
1. User opens a recognized dApp.
2. User requests wallet connection.
3. User reviews the connection request and selected account/network.
4. Later requests to sign or transact are reviewed separately.

**Key warning:** Connection alone may not move assets, but a signature or approval can have consequences.

## User approves a token permission
1. A dApp asks permission to use a token.
2. User sees who is requesting permission and the allowance scope.
3. User chooses a limited amount whenever that fits the use case.
4. User confirms only after understanding why the permission is needed.

**Key warning:** Unlimited approval can increase exposure if the dApp or connected account is compromised.

## User moves assets across networks
1. User chooses source network, destination network, token, amount, and receiving address.
2. User reviews fee, estimated output, and route information.
3. User confirms the source transaction.
4. User waits for the cross-network process and then checks the destination side.

**Key warning:** Completion time and received amount may vary; bridge activity carries third-party and network risks.

## User uses AI assistance
1. User asks a practical question, such as understanding a transaction or comparing available options.
2. The assistant explains information and flags uncertainty or risk.
3. The user reviews the actual transaction screen.
4. The user makes the final decision and confirms independently.

**Agent guidance:** The AI supports understanding; it must never pressure users to transact.
